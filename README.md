# Кандидатогенерация услуг Авито

Это зафиксированное решение `agent_3/e3_four`: четыре канала поиска и ансамбль
из трёх LightGBM. Файл для платформы — **`answer.csv` в корне**.

| Выборка | Запросов | Recall@50 | 95% bootstrap CI |
|---|---:|---:|---|
| validation | 2 000 | 0.9400 | [0.9293, 0.9503] |
| held-out test | 2 000 | 0.9276 | [0.9165, 0.9393] |
| benchmark платформы | 2 452 | разметка недоступна | — |

Локальный test не является приватным тестом платформы. Содержимое benchmark
CSV воспроизводится точно; его качество на платформе станет известно после загрузки.

## Запуск

Проверенная среда: Linux x86_64, Python 3.13, 3 потока CPU. Для обычного
воспроизведения не нужны CUDA, PyTorch, доступ к Hugging Face или внешним API.

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py predict --output reproduced_answer.csv
.venv/bin/python run.py check --file reproduced_answer.csv
.venv/bin/python run.py verify
```

Установка библиотек — подготовка среды. Все вычисления после установки идут
локально. Для установки в среде без сети нужны заранее установленные версии
из `requirements.txt` или локальные wheels этих библиотек.

`verify` заново строит объединение кандидатов и признаки, применяет модели,
сравнивает SHA-256 всех трёх CSV с исходными и считает метрики через исходный
общий harness. Отчёт записывается в `runtime/verification_report.json`.
Проверка использует эталонные CSV только для сравнения после расчёта предсказаний.

При первом запуске большие входы и промежуточные артефакты извлекаются из
`bundle/` в `runtime/`. Проверяются SHA-256 частей и собранных файлов.
Не удаляйте `bundle/`, `bundle_manifest.json`, `models/` и `release.json`.
Удаление `runtime/` безопасно: следующий запуск создаст его заново.

## Состав репозитория

- `run.py` — воспроизведение, проверка формата, проверка идентичности и обучение.
- `src/avito_solution/` — расчёт признаков и LightGBM.
- `src/avito_bootcamp_2026/` — исходные загрузчики и общий harness оценки.
- `models/` — три обученные модели с seeds 17, 23, 42.
- `bundle/` — исходные benchmark-входы, нужные колонки истории, split v1,
  embeddings, четыре retrieval-канала и таблицы признаков до финального ранжирования.
- `answer.csv` — файл, который нужно загрузить на платформу.
- `verification/` — эталонные ответы, исходные метрики и отчёт проверки поставки.
- `SOLUTION.md` — данные, алгоритмы, валидация, анализ ошибок и ограничения.
- `THIRD_PARTY.md` — используемые открытые библиотеки и модель.
- `provenance/` — исходники генерации артефактов и параметры эксперимента.

Большие файлы разбиты на части по 32 MiB. Ни один файл для Git не превышает
100 MB. `runtime/` игнорируется Git и не нужен при передаче папки.
Поставляются численные кеши retrieval и embeddings: это вычисленные
промежуточные результаты алгоритмов на фиксированном корпусе. Итоговый ранкер
не использует таблицу готовых ответов по query_id, ручные ответы или test qrels.

## Обучение ранкера заново

```bash
.venv/bin/python run.py train
.venv/bin/python run.py verify --models-dir runtime/retrained_models
```

Этот режим строит rtrain-признаки и обучает исходные три seed. Разметка val/test
в обучение не входит. Точное воспроизведение поставленного результата
гарантируется проверенным запуском с поставленными checkpoints и артефактами;
перенос обучения или GPU-encoding на другие версии/оборудование может изменить
числа. Для исходного протокола получения embeddings см. `provenance/agent_2/`:
использовалась закреплённая версия e5-base. Повторно скачивать или считать
embeddings для воспроизведения не требуется.

## Как передать решение

`task.md` требует сначала загрузить **answer.csv**, а код передать как
репозиторий или notebook с описанием. Папка подготовлена как корень такого
репозитория. Не нужно переносить весь рабочий проект с экспериментами.

Если система принимает папку/архив: передайте содержимое этой папки целиком,
кроме `.venv/` и `runtime/`. Если она принимает ссылку на Git:

```bash
cd /путь/к/avito_submission
git init
git add .
git commit -m "Reproducible Avito candidate generation solution"
git branch -M main
git remote add origin <URL_ВАШЕГО_ПУСТОГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

Проверьте доступ проверяющего к репозиторию. Это обычный репозиторий без Git LFS:
все части `bundle/` должны попасть в push. На платформу с попытками отправляется
отдельно `answer.csv`; Git push не отправляет предсказания на платформу.
